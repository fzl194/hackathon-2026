# 第14题全貌：把知识点映射回交付物

[Wiki首页](README.md) · 前置：[概念地图](基础/概念地图.md)

本题要交付一个PostgreSQL向量索引扩展：数据超内存时仍能做近似Top-K搜索，支持高维、条件过滤、动态增删改，并遵守数据库事务与并发规则。

## 从熟悉的问题逐层增加约束

```text
数组上的Top-K
  → 用索引减少工作
  → 数据超内存，控制磁盘访问
  → 带条件查询与持续增删改
  → 多用户并发、提交/撤销和恢复
  → 接入PG并按规定框架评测
```

## 算法和数据库为什么要一起考虑

一个独立ANN库可能搜索很快，却不能自动处理事务回滚或PG崩溃恢复。成熟数据库扩展可能正确性较完善，却在超内存、高维或过滤方面存在功能和性能缺口。

当前研究方向是先确认可用基础的要求覆盖，再选择修改层次；尚未确定最终实现，更没有证明某种组合可以获奖。所有实验仍待执行。
