# IVF：先分组，再检查部分分组

[Wiki首页](../README.md) · 前置：[KD-tree](KD-tree.md) · 下一页：[HNSW](HNSW.md)

IVF是Inverted File的缩写。在向量搜索里，可以先理解成“每个分组对应一份向量列表”的索引组织方式。

## 建索引时做什么

以常见的聚类分区方案为例：先从数据样本学习一批中心，每个向量分配给一个中心对应的列表。

```text
中心1 → 向量3、向量7、向量18……
中心2 → 向量1、向量6、向量12……
中心3 → 向量2、向量4、向量15……
```

可以把中心想成街区代表点，列表里存属于该街区的点。名称虽有inverted，并不意味着必须先理解文本搜索倒排索引。

## 查询时做什么

1. 比较q与各中心的距离，选择若干接近的列表。
2. 扫描这些列表里的候选。
3. 计算或估计候选距离，维护Top-K。

假设100万个点分成1000个大小近似相等的组，只检查5组，候选约5000个。这里只是均匀分组的算术例子，真实数据会有组大小差异，选择中心也要花成本。

## 为什么可能漏答案

接近某个中心，不保证真正最近邻一定属于该组。查询和答案可能在分区边界两侧；只查少数组就可能遗漏。

常见参数`nlist`控制分组数，`nprobe`控制搜索多少组。pgvector IVFFlat的同类参数叫`lists`与`probes`。搜索更多组通常更准、更慢；搜索全部列表并对所有原向量计算距离，可以恢复精确扫描的答案。

这与KD-tree安全剪枝不同：只搜索最近几个组通常是一种预算选择，不是证明其他组绝无更近点。

## IVFFlat和IVF-PQ

|名称|分区里的数据|距离与成本|
|---|---|---|
|IVFFlat|保存原始向量表示|候选距离可精确计算，但可能漏查整个列表|
|IVF-PQ|采用PQ等压缩编码|进一步降低表示成本，同时引入近似误差|

聚类中心和PQ码本的学习是索引构建训练，不是重新训练embedding模型。它仍占构建时间，数据分布变化也可能影响分组质量。

## 与本题的关系

分区方案值得理解，但是否适合受限内存、过滤、动态和全部距离，需逐项验证。即使每组容易顺序扫描，也不能只凭直觉宣布优于磁盘图搜索。
