# 量化与重排序

[Wiki首页](../README.md) · 前置：[距离与向量类型](../基础/距离与向量类型.md)

量化用更少比特近似表达向量；重排序在候选集合内用更准确的距离重新挑选Top-K。它们常与IVF或图索引组合。

## 已经理解量化定义后，需要再分清三件事

|问题|含义|
|---|---|
|怎样存|每个向量的编码占多少字节？|
|怎样算|怎样从编码估计距离，花多少CPU成本？|
|怎样补精度|保留多少候选，是否读取原向量重排？|

压缩可能同时影响内存、I/O和计算，也可能让更多候选被错误地提前排除。因此不能只看压缩倍数。

## 一个PQ编码例子

8维float32坐标载荷为32字节。把它切成4段，每段2维；每段准备256个代表向量，称码字。用1字节保存最近码字的编号，4段总计4字节，不计共享码本和其他元数据。

搜索时利用码本和编码估计距离，避免每个候选都读取全部原始坐标。这只是编码原理示意，不是本题参数建议或实测压缩比。

PQ码本通常需要样本学习；float16转换、二值量化和PQ是不同方式，不应混为一种算法。压缩索引也不意味着用户原向量必须永久丢弃。

## 重排序做什么

假设最终要10个答案，先利用压缩距离得到100个候选，再读取这些候选的原向量，计算准确距离，选出其中最近10个。

它能纠正候选内部的排序误差，但真正近邻若完全没进入这100个候选，重排就无法恢复。

```text
漏查了答案所在区域 → 重排救不回
答案已在候选中，只是压缩排序不准 → 重排可能纠正
```

## 与本题的关系

量化有助于减少高维导航表示和内存占用。代价可能是更多候选或原向量读取；最终要同时比较召回、QPS、构建时间与磁盘大小。原数据、导航编码、重排数据要分别记账。
