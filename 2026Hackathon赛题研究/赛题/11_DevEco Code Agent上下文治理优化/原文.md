# DevEco Code Agent上下文治理优化

 

# 2       背景信息

业界OpenCode等代码生成工具受限于大模型上下文窗口长度和推理成本，采用短上下文设计（通常仅支持8K-32K Token）。在处理复杂代码任务时，由于历史记忆易缺失导致代码生成质量严重下降。具体表现为：代码补全不准确（准确率下降约35%）、跨文件依赖理解不足（相关代码召回率仅约45%）、长期任务规划能力弱（多步骤任务完成率低于50%）。

DevEco Code Agent采用了长上下文（128K+）的技术路线。但是长上下文场景下有效信息被淹没在大量冗余内容中，造成KV Cache利用率低下（当前约35-40%）、推理延迟增加（端到端延迟可达2-3秒）、吞吐量下降（并发能力降低约40%）。

Agent上下文治理具有以下**难点**：

1. **多维度重要性评估难以精准**：判断过往记忆对当前任务是否有价值贡献，避免误删关键上下文导致生成质量断崖式下降，同时精准过滤无价值冗余信息的评估体系设计困难。

2. **知识检索难以平衡召回率与精确率**：从海量知识库内容中精准筛选与任务相关的知识片段，召回率高但精确率低、信息密度稀疏导致有效上下文利用率不足。

3. **工具输出压缩难以兼顾关键信息保留**：对工具输出内容进行有效信息提取与压缩，在保留关键业务数据和执行结果的前提下剔除低价值内容，平衡难度大。

# 3       问题描述

本难题期望构建智能上下文治理系统，包含两个核心模块：

1.信息重要性分析（在压缩之前）：对输入的上下文信息进行多维度重要性评估。

综合考虑与当前任务的语义匹配度、是否为新信息、历史效用等因素，识别出对当前任务最关键的记忆片段、知识库内容和工具使用记录。评估模型需在100ms内完成单次评估。

 

2.自适应压缩与治理（在评估之后）：根据可用上下文窗口大小和任务类型，动态选择最优压缩策略。

压缩策略包括：选择性保留（保留高重要性条目，丢弃低重要性条目）、摘要压缩（对长文档进行关键信息提取，压缩比可达3-5倍）、去重合并（合并重复或相似的上下文内容）。在保留关键信息的同时去除冗余内容，确保语义完整性。

# 4       期望达到的指标和效果

**系统约束**

- 代码生成效果指标不劣化

**系统目标**

在满足**系统约束**的前提下。尽最大可能提升上下文压缩率、首token时延TTFT和一次处理复杂请求数量。

具体评分规则参考第七部分。

# 6       评选标准

**不满足系统约束不得分**

**满足系统约束的前提下，按以下标准评分**：

- 上下文长度压缩（60%）：最大化上下文长度压缩。达成或由于理想压缩率（25%）的，按照排名得分在30-60分布；劣于理想的，按照排名得分在0-30分布。
- 首Token时延TTFT（40%）：达成或由于理想时延降低（25%）的，按照排名得分在20-40分布；劣于理想的，按照排名得分在0-20分布。
