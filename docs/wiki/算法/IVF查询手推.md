# IVF查询手推：只查最近的分组，怎样漏掉答案

[Wiki首页](../README.md) · 前置：[IVF](IVF.md)、[KD-tree查询手推](KD-tree查询手推.md) · 后续：[HNSW](HNSW.md)

本页沿用同样8个二维点，对比有限分组搜索与精确剪枝。示例不使用量化，候选距离全部按原坐标准确计算；仍然可能遗漏答案。

## 1. 搜索目标

q=(4,4)，查Top-2：

|点|坐标|到q的L2平方|
|---|---|---|
|A|(1,1)|18|
|B|(2,2)|8|
|C|(3,3)|2|
|D|(4,5)|1|
|E|(6,4)|4|
|F|(7,4)|9|
|G|(8,8)|32|
|H|(9,9)|50|

精确答案是D、C。每篇保留数据，方便独立打开本页阅读；实际基准成绩仍集中维护在[公开基准现状](../../公开基准现状.md)。

## 2. 给定中心并分配列表

为了便于手算，手动指定3个中心：c1=(2,2)，c2=(6,4)，c3=(8.5,8.5)。它们不是本项目运行K-means得到的结果，也不要求恰好等于各列表均值；这里只演示给定中心后的分配与查询。

每个点放入距离最近中心的列表，得到：

```text
c1 → A、B、C
c2 → D、E、F
c3 → G、H
```

例如C到c1距离平方为2，到c2为10，到c3为60.5，所以进入c1；D到c1为13，到c2为5，到c3为32.5，所以进入c2。

真实IVF通常先从样本学习分区，再分配数据；中心构建质量会影响性能。本页把这一环固定下来，只研究查询过程。

## 3. 查询与中心比较

|中心|到q的L2平方|访问优先级|
|---|---|---|
|c2|4|第一|
|c1|8|第二|
|c3|40.5|第三|

`nprobe`控制检查多少列表。先令nprobe=1，只查c2。

## 4. 只查c2时发生什么

候选只有D、E、F，到q距离平方依次为1、4、9，因此返回D、E。

```text
精确Top-2：D、C
实际返回： D、E
找对1个 → recall@2 = 1/2 = 0.5
```

C确实比E近，但它被分配到c1，整个列表没有被访问。这里没有距离计算误差，也没有PQ压缩误差；误差来自候选覆盖不足。

## 5. 为什么不能用中心距离当作列表距离下界

q到c1的距离平方为8，但同组的C到q只有2。因此“中心比较远”不代表“该组所有点都远”。

与KD-tree不同，只查最近的1个中心通常是预算决定，并未证明其他列表无法改善答案。IVF也可以另加几何界或其他机制，但本页没有使用。

## 6. 增加nprobe

|nprobe|检查的列表|扫描原始点数|返回|recall@2|
|---|---|---|---|---|
|1|c2|3|D、E|0.5|
|2|c2、c1|6|D、C|1.0|
|3|全部|8|D、C|1.0|

本例第2组已补回答案，但没有保证对其他查询也如此。若搜索全部列表、保留所有点并准确计算距离，就能得到这套原始数据的精确答案。

每次还要算3个中心距离，并承担列表访问等开销。例如nprobe=2是3次中心距离＋6次原始点距离，不能因只扫描6个原始点，就说总成本一定低于暴力的8个点。教学小例不用于比较实际速度。

## 7. 哪些参数属于建索引，哪些属于搜索

- `nlist`：预先分多少组，影响构建、中心比较和列表规模。
- `nprobe`：一次查询检查多少组，常可在不重建整个索引的情况下调整。
- pgvector中的同类名字为`lists`和`probes`，不能直接将某库参数原样当成本题接口。

因此一份建好的索引可以测多个搜索预算，形成不同召回—速度点。增加分组数并不自动更好，因为中心查找、列表访问与分组质量也有成本。

## 8. 自检

对nprobe=1得到的D、E，再计算一次精确距离，能不能恢复C？不能，C没进入候选集合。这是后续理解[量化与重排序](量化与重排序.md)的重要边界。

接下来学习HNSW时，留意它把“选哪些列表”换成了“沿图访问哪些节点”，同样需要控制候选覆盖和搜索预算，但导航结构不同。
