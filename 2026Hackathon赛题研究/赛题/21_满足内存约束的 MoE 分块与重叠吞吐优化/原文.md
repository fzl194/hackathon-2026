# 满足内存约束的 MoE 分块与重叠吞吐优化

## 1. 背景

在大模型训练中，MoE（Mixture of Experts）层把「一份大 FFN」换成 E 个小专家：每个 token 只被路由到少数几个专家，由这些专家所在的 NPU 完成计算。这样可以在算力基本不变的前提下把参数量放大一个数量级——代价是**数据要流动**：token 必须先被送到专家所在的卡上，算完再送回来。

为了让集群跑得快，系统通常同时使用两种并行方式：

- **专家并行（Expert Parallelism, EP）**：把同一层的 E 个专家分到不同的 NPU 上。token 通过 AllToAll 被送到目标专家所在的卡，算完再 AllToAll 回来。
- **管线并行（Pipeline Parallelism, PP）**：把 L 层切成若干段（stage），microbatch 像流水线一样依次流过各段。DualPipe 等方案会让 microbatch 从两端同时注入，以减少空泡。

这两件事互相纠缠：EP 决定 AllToAll 走节点内还是跨节点（两者带宽往往差一个数量级），PP 决定哪些层在同一张卡上、以及流水线的空泡有多少；而每张卡的 HBM（高带宽内存）是硬上限，专家参数、通信缓冲、激活值都抢同一块内存。

**本题：** 给定集群拓扑、每卡内存、模型规模与逐层负载，输出一份完整映射（网格、切层、逐层专家放置、整步调度），使一步训练的 wall-clock time 最小，且每张卡均不超过内存上限。

### 问题难点

三层决策耦合在一起：

- **网格** (V,P,D)：stage 数、专家并行规模、数据并行度。它决定每卡要驻留几个专家（每层 E/P 个），也是专家参数占用内存的直接来源；它还决定通信对端分布在几个节点上，从而决定流量走节点内还是跨节点。
- **切层** ψ：L 层怎么连续切成 V 段。它决定哪些层共卡，因而决定每张卡的内存预算，也决定最慢的那个 stage 有多慢。
- **调度**：通信与计算在时间轴上如何交错。它决定全部重叠与空泡，同时决定某一时刻有多少缓冲与激活还没释放。

目标时间由「最挤的通信边」「最慢的 stage」「最长的调度链」这类最大值决定：任何一处瓶颈都会被 max 直接放大到总时间里，优化的本质就是把这些最大值压下去（min-max 型瓶颈优化）。三者共用同一套时间与内存公式，无法分别求解。

### 商业价值

MoE 是主流大模型的核心结构，EP/PP 联合映射直接决定训练吞吐与显存占用。自动化的映射搜索可降低大模型训练对专家调参的依赖，为 AI 编译器与集群调度栈提供可复用的布局能力。

### 1.1 一次前向的四个步骤，与四种参考排法

一个 MoE 层在每张卡上的前向过程包含四个步骤：

1. **共享专家**：所有 token 都经过它。纯计算，不涉及跨卡通信。
2. **分发 AllToAll**：把本地 token 按路由结果发给目标专家所在的卡。纯通信。
3. **GroupGEMM**：计算落在本卡的专家。纯计算。
4. **汇集 AllToAll**：把专家的输出送回 token 原来的卡。纯通信。

反向对应地产生六个步骤：共享专家的输入梯度与权重梯度、专家输入的梯度与专家权重的梯度、以及分发与汇集各自的反向通信。

**前向四个、反向六个，合计十个步骤。** 第 4.1 节给出这十个步骤各自占用的引擎与时长。

**关键点：通信占用通信引擎，计算占用计算引擎，两类资源互不冲突，因此可以同时进行。** 每个 NPU 的通信能力与计算能力都是固定的，调度只能决定二者如何交错，不能把一方让给另一方。串行执行时（通信时算力闲置、计算时网络闲置）一段的时间就是各段之和；让通信与计算重叠，一段的时间就接近两者中的较大者。这就是本题全部收益的来源。

**但重叠不是免费的，也不是自动的。** 同一个 microbatch 内部这四个步骤有严格依赖：分发必须等共享专家算完，GroupGEMM 必须等本卡的 token 全部到齐（即分发完成），汇集又必须等 GroupGEMM 产出结果。每一个步骤都要等前一个步骤结束，所以一个 microbatch 无法与自己重叠。**单看一个 microbatch，无论怎么排都只能串行。** 重叠只能来自**不同 microbatch 之间**或**不同层之间**的交错——这正是调度要解决的问题。

**这四种排法只是背景材料：判分只看第 4 节的模拟结果，选手的调度不限于这些排法，也不必与其中任何一种对应。**

下表是四种经典排法，本节只说明思路，精确时长见第 4 节：

| 参考排法 | 做法 | 特点 |
| --- | --- | --- |
| **SER**（无重叠） | 各段严格串行 | 时间最长，但缓冲最小：任何时刻只有一段在用缓冲 |
| **CHK**（切块重叠） | 把一层内各段切成小块流水推进：第 i 块的 AllToAll 与第 i+1 块的 GroupGEMM 同时进行 | 需要两套引擎同时为同一层工作；未完成的块越多，缓冲越大 |
| **SHR**（共享专家重叠） | 共享专家的计算与两个 AllToAll 同时进行 | 用共享专家填补通信造成的算力空档 |
| **UNI**（融合） | 把 AllToAll 与 GroupGEMM 放进同一 kernel，两套引擎同时对同一 microbatch 工作 | 通信可被计算掩盖；共享专家成为串行前缀 |

**这四种不是必须选择的模板**：参赛者提交的是完整调度，上述四种只是其中的特殊排法。调度的一般性正是本题给参赛者的主要自由度之一。

## 2. 输入

所有量均为非负整数，同一行以空白分隔。

本题不模拟真实时钟：**所有时间量都以同一个抽象「时间单位」计**，`Time` 的绝对数值没有物理含义，只用于排名比较。带宽 Bin​,Bout​ 的单位是字节/时间单位，时间系数 Fs​,Fio​,Fin​ 的单位是时间单位。

**第 1 行** N S M Bin​ Bout​：集群与内存。

| 符号 | 含义 |
| --- | --- |
| N | 节点数 |
| S | 每节点 NPU 数；总卡数 R=N⋅S |
| M | 每卡 HBM 上限（字节） |
| Bin​ | 节点内带宽（字节/时间单位）。同节点通信都走它，通常远大于跨节点带宽 |
| Bout​ | 节点间带宽（字节/时间单位），Bout​≤Bin​ |

**第 2 行** L E Z Zs​ U Uact​ k nmb​ Fs​ Fio​ Fin​ α×​ β×​：模型规模、缓冲与时间系数。

| 符号 | 含义 |
| --- | --- |
| L | MoE 层数 |
| E | 每层可路由专家数（逐层相同） |
| Z | 单个可路由专家参数大小（字节）。每卡每层驻留 E/P 个专家，故每层占用 (E/P)Z 字节 |
| Zs​ | 共享专家大小（每卡每层一份，可为 0） |
| U | 一块通信缓冲的字节数。每个 stage 只有一套通信引擎（4.2 第 3 条），同一 stage 内同时最多一块通信在途，占用 U 字节；见 4.6 |
| Uact​ | 一个 (microbatch, 层) 的激活值字节数；见 4.6 |
| k | 每个 token 路由到的专家数（top-k，逐层相同） |
| nmb​ | microbatch 数（偶数）。它决定流水线里同时有多少个 microbatch 处于推进状态 |
| Fs​ | 共享专家时间系数（每 slot）：一个 slot 的共享专家要占多少时间单位 |
| Fio​ | AllToAll 通信系数（每单位带宽时间的时间单位，见 4.4） |
| Fin​ | GroupGEMM 计算系数（每 slot 占多少时间单位，见 4.3） |
| α×​,β×​ | 反向系数（微单位）：α=10−6α×​，β=10−6β×​。前者是「一次反向约等于几次前向」，后者是「权重梯度占反向的多少」 |

**第 3 行** d b：隐层宽度（元素数）与元素字节数。每个 token 的激活为 d⋅b 字节，分摊到它路由的 k 个专家上，故每 slot 交给一个对端的载荷为 H=⌊db/k⌋ 字节。**H 不是输入，而是由 d,b,k 导出。** 建模时假定各 MoE 层的隐层宽度与元素类型相同，因此单 slot 的字节数不随层变化；逐层可变的是各层的负载，见下面每层的输入行。

**第 4 行起共 L 行**，每行描述一层的负载。第 ℓ 行为 Tℓ​ 与可选负载向量：

- Tℓ​ 是层 ℓ 的 token-slot 数（top-k 已展开，即 Tℓ​=k⋅Bℓ​，其中 Bℓ​ 是该层 token 数）。
- 若该层负载均衡，该行只写 Tℓ​。
- 否则在其后写 E 个整数 aℓ,0​…aℓ,E−1​，表示路由到各专家的 slot 数，满足 ∑e​aℓ,e​=Tℓ​。

需要注意的是，输入给出的是**一个静态的负载分布**：每层每个专家分到多少 slot 在输入里是确定的，不随训练步变化。建模时也不假定它均匀——真实训练中门控输出天然偏斜，且各层偏斜程度不同。负载既然已知，专家怎么放（见 4.3 节）就是一个可以据此优化的决策。

物理卡嵌入由评测器按规范映射固定：q=v⋅(P⋅D)+d⋅P+p（p 最快变）。要求 P∣S 或 S∣P，使 EP 组与节点对齐——这条约束保证一个 EP 组要么完全落在节点内，要么整齐地跨节点，从而「节点内对端数」是确定的。

## 3. 输出

按以下格式输出完整映射：

```
V P D
PSI
ψ_1 ψ_2 ... ψ_{V-1}
MAP
σ_0,0 σ_0,1 ... σ_0,E-1
...
SCHEDULE
t mb:ℓ:op mb:ℓ:op ...
...
```

### 3.1 逐字段说明

| 字段 | 含义 |
| --- | --- |
| `V` | 管线 stage 数（沿层切分） |
| `P` | 专家并行规模（同一层专家切到几个 rank） |
| `D` | 数据并行度（V⋅P⋅D=R） |
| `PSI` | 层切点 ψ1​,…,ψV−1​，严格递增；V=1 时为空行。stage v 含层 [ψv​,ψv+1​) |
| `MAP` | 逐层专家放置，共 L 行。第 ℓ 行是 E 个整数 σℓ,e​∈[0,P)：专家 e 放在本 EP 组的第几个 rank。每个取值恰好出现 E/P 次 |
| `SCHEDULE` | 整步调度，见下 |

### 3.2 调度格式

调度是一张时间表。**每一行是一个时刻**，行首是整数时刻 t，其后是若干个操作，写作 `mb:ℓ:op`：

- `mb` 是 microbatch 编号，范围 [0,nmb​)；
- `ℓ` 是层号，范围 [0,L)，它属于哪个 stage 由 `PSI` 决定，因此条目里不必再写 stage；
- `op` 是操作名，取自 4.1 节的十种。

**同一行内的所有操作在同一时刻开始并发执行。** 若需要区分同一层同一操作的多个实例（例如把一次 AllToAll 切成两块），加后缀即可：`0:0:disp.a` 与 `0:0:disp.b` 是两个独立的通信操作，各自占用一次引擎。

**这张表里同时写着 V 条时间线，每个 stage 一条。** stage 由 `ℓ` 经 `PSI` 推出，因此不必为每个 stage 单独写一段：同一行内可以出现属于不同 stage 的操作，那表示这些操作各自在自己的卡上同时开始。每个 stage 独占一套计算引擎与一套通信引擎（见 4.2 第 3 条），stage 之间只通过「同一 microbatch 的前向按 stage 顺序推进」这一依赖相连，并不共享引擎，因此各 stage 的排法可以完全不同——这正是流水线能错开推进的原因。7.5 节给出了两条时间线同时展开的例子。

三条格式约定：

1. t 必须非降——调度按时间顺序书写。
2. 同一行内不得出现两个占用同一引擎的操作（具体规则见 4.2）。
3. 行与行之间不必等距：某一行写完，直接写下一个有新操作的时刻即可。

一个最小的完整例子（对应 7.1 节）：

```
1 2 1
PSI

MAP
0 1
SCHEDULE
0 0:0:s
16 0:0:disp
86 0:0:gemm
110 0:0:comb
```

读法：时刻 0 开始共享专家（时长 16），时刻 16 开始分发（时长 70），时刻 86 开始 GroupGEMM（时长 24），时刻 110 开始汇集（时长 70）。最后一次操作在 110+70=180 结束，故 Time=180。

参考排法与切块数 K 不再出现在输出中：K 所表达的分块，由调度中操作实例的个数与位置直接体现。这是本题把「选模板」升级为「写调度」的直接后果——自由度更大，但也要自己保证依赖与资源都合法。

## 4. 得分计算（模拟过程）

### 4.1 十种基本操作

每个操作占用两套引擎之一，时长由该层的 Tℓ​、H 与全局系数决定。记号：mℓ​ 为该层最慢 rank 承载的 slot 数（见 4.3），xℓ​ 为该层一次 AllToAll 的时长（见 4.4），sℓ​=Tℓ​Fs​ 为共享专家时长。

| 操作 | 引擎 | 时长 | 含义 |
| --- | --- | --- | --- |
| `s` | 计算 | sℓ​ | 共享专家前向 |
| `disp` | 通信 | xℓ​ | 分发 AllToAll |
| `gemm` | 计算 | mℓ​Fin​ | 落在本卡的专家前向 |
| `comb` | 通信 | xℓ​ | 汇集 AllToAll |
| `s_bwd` | 计算 | αsℓ​ | 共享专家输入梯度 |
| `comb_bwd` | 通信 | αxℓ​ | 汇集反向 |
| `gemm_dx` | 计算 | αmℓ​Fin​ | 专家输入梯度 |
| `gemm_dw` | 计算 | αβmℓ​Fin​ | 专家权重梯度 |
| `disp_bwd` | 通信 | αxℓ​ | 分发反向 |
| `s_dw` | 计算 | αβsℓ​ | 共享专家权重梯度 |

所有时长向上取整为整数。系数满足两条常识：一次完整反向约等于 α 次前向（线性层反向有两个 GEMM，故 α 接近 2），其中权重梯度占 β（两个 GEMM 差不多大，故 β 接近 0.5）。把反向拆成这六个步骤而不是当成一整块，是为了让参赛者能把权重梯度这类不占通信的步骤塞进空泡里——这正是 ZB1P 一类的思路。

### 4.2 依赖与资源

合法调度必须满足：

1. **层内依赖**：同一 (microbatch, 层) 的前向顺序固定为  
   `s → disp → gemm → comb`；反向顺序固定为  
   `s_bwd → comb_bwd → gemm_dx → gemm_dw → disp_bwd → s_dw`。  
   前一段完成后，下一段才能开始。
2. **管线依赖**：同一 microbatch 在 stage v 的前向全部完成后，才能开始 stage v+1 的前向；反向相反。同一 microbatch 的反向依赖其前向完成。
3. **资源互斥**：同一时刻内，**同一 stage** 上不得有两个计算类操作，也不得有两个通信类操作。不同 stage 位于不同的物理卡上，各有一套引擎，因此互不影响——这是重叠的主要来源。
4. **局部性**：操作引用的层必须属于它所在的 stage。
5. **因果性**：条目声明的 t 不得早于其依赖的完成时刻；违反则该映射非法。

计算类操作由该 stage 内**最慢的一张卡**决定，故取 mℓ​ 而不是平均值：一个 rank 上的专家越热，整层就要等它。

负载均衡时 mℓ​=⌈Tℓ​/P⌉，与常规公式一致；负载偏斜时 mℓ​ 还取决于 `MAP`——把热点专家分散到不同 rank 就能压低 mℓ​。注意通信量 Xℓ​ 只依赖总量 Tℓ​（见 4.4），所以**偏斜只抬高计算、不改变通信**，两类引擎对偏斜的敏感度不同。

### 4.4 通信时间

每 rank 每层发往远端 peers 的字节数为

Xℓ​=⌈Tℓ​HPP−1​⌉,H=⌊kdb​⌋.

EP 组占据的物理卡集合由嵌入确定。记该 rank 在组内的**节点内对端数** pin​ 与**跨节点对端数** pout​=P−1−pin​（由嵌入直接算出，不由参赛者选择）。该层一次 AllToAll 的时长按最慢的一类对端计：

xℓ​=max(⌈Bin​pin​Xℓ​​⌉, ⌈Bout​pout​Xℓ​​⌉)⋅Fio​.

流量按**实际对端数**分项，不随 P 线性外推。这样做的理由很实际：跨节点带宽通常比节点内低一个数量级，把 P 调大虽然能摊薄每卡计算量，却会把越来越多流量推上窄带，两者必须显式权衡（见 7.3 节）。

### 4.5 一步训练时间

给定 (μ,V,P,D)、ψ、σ 与调度，评测器：

1. 按 4.1、4.3、4.4 算出每个操作被引用时的时长；
2. 按 4.2 检查依赖与资源，模拟得到每个操作的实际起止；
3. 一步训练时间取所有操作完成时刻的最大值：

Time=所有操作max​(t+时长).

评测器只做前向模拟，**不做任何优化或搜索**：调度由参赛者给出，评测器只负责判分。这也是为什么参赛者可以自由使用任何启发式甚至不完整的搜索——评测器不需要知道最优值是多少。

### 4.6 每卡内存

物理卡 q=v⋅(P⋅D)+d⋅P+p 上只有 stage v 的层。三块占用：

Mexp​(q)Movl​(q)Mact​(q)​=ℓ∈stage v∑​(PE​Z+Zs​),=U⋅tmax​ #{时刻 t 上已开始未完成的通信操作},=Uact​⋅tmax​ #{时刻 t 上前向已完成、反向未完成的 (mb,ℓ)}.​

三块的直觉分别是：

- Mexp​ 是静态的：放几个专家就吃几份参数，且按层数线性累加。这是「切层」与「网格」直接影响的内存。
- Movl​ 是通信缓冲：每个 stage 只有一套通信引擎（4.2 第 3 条），同一 stage 内同时最多只有一个通信操作在飞，因此给定 V 时它是常数（该 stage 有通信时为 U，否则为 0）。
- Mact​ 是激活值，也随调度变：前向铺得越开、反向压得越后，同时活着的激活就越多。

Movl​ 里的通信操作指 `disp`、`comb`、`comb_bwd`、`disp_bwd` 四种。必须对每张卡满足 Mexp​+Movl​+Mact​≤M，否则该映射非法，得 0 分。

### 4.7 合法性约束

1. V⋅P⋅D=R，V,P,D≥1，P∣E，且 P∣S 或 S∣P；
2. 切点严格递增且覆盖 0..L；
3. `MAP` 每行合法：σℓ,e​∈[0,P)，每个取值恰好出现 E/P 次；
4. 调度满足 4.2 的五条规则，且只引用 4.1 表中的操作名；
5. nmb​ 为偶数（输入保证）。

### 4.8 三种经典方法作为特例

下列三种排法是流水线调度的常见写法，都可以用 `SCHEDULE` 表达；参赛者不必局限于此，任何满足 4.2 的调度都可以提交：

- **1F1B**：每个 stage 稳定地按「一次前向、一次反向」交替推进；
- **ZB1P**：把反向拆成输入梯度与权重梯度两个步骤，令权重梯度填补空泡；
- **DUALPIPE**：microbatch 从两端同时注入，同一张卡同时持有前后两端的 microbatch。

## 5. 评测方式

1. 求解器对每个测试点输出一份完整映射。测试点保证存在合法映射，因此不需要输出无解标记。
2. 映射非法、越界、解析错误，该测试点记 0 分。
3. 合法输出由评测器按第 4 节模拟得到 Time，**Time 越小得分越高**；各测试点按相对成绩聚合排名。并列时先比较求解器 CPU 时间，再比较提交时间。
4. 每个测试点的运行时限为 10 秒（墙钟时间，评测器自身的模拟耗时不计入）；超时该测试点记 0 分。

本题不要求精确最优解，鼓励在时间预算内探索不同的映射与调度策略：评测器只负责模拟判分，因此选手可以自由取舍搜索的深度与广度。

## 7. 样例

下面六个样例都给出输入与输出，便于对照格式；说明中的数值均可由第 4 节公式手算复核，各输出也都满足第 4.7 节的合法性约束。

**这些输出是可行解，不是最优解**，只用于说明格式与机制：清单里的数值全部取自第 4 节的公式，但排法本身没有经过优化，每个 `SCHEDULE` 都还有压缩空间（更细的切分、更紧的交错、更好的 `MAP`）。样例的规模被压到可以手算，真实规模下能拉开差距的那些优化在这里往往没有充分展开。样例也不代表测试点的规模与难度：测试点按第 6 节的范围生成，L 与 E 都可以远大于这里，且样例不需要满足第 6 节的取值范围（例如 7.1、7.5、7.6 的 E=2）。

### 7.1 样例 1（单 microbatch 只能串行，交错来自两个 microbatch）

**输入**

```

1 2 20 0 1 1 1 2 2 10 6 1000000 1000000
8 2
8
```

R=2，同节点。H=⌊8⋅2/1⌋=16，X=⌈8⋅16⋅1/2⌉=64，pin​=1，pout​=0，x=⌈64/10⌉⋅10=70。P=2 时每 rank 一个专家，m0​=⌈8/2⌉=4，故 `gemm`=4⋅6=24；`s`=8⋅2=16。

**内存把 P 顶起来了**：M=39，而 P=1 要让每张卡独吞 2 个专家（2×20=40 字节参数）就已经超了，所以 P≥2；P=2 时每卡只放 1 个专家，参数 20 字节，加 1 块缓冲共 21 ≤39，可行。

**输出**

```

156 0:0:comb 1:0:gemm
```

**说明**：nmb​=2，一步里有两条 microbatch 的工作，共 20 个操作。**单个 microbatch 内部四个步骤严格依赖**（分发要等共享专家、GroupGEMM 要等分发、汇集要等 GroupGEMM），所以它自己无法重叠，单独跑一条要 16+70+24+70=180；两条 microbatch 之间没有依赖，可以交错，于是通信与计算得以重叠。

**输入**
