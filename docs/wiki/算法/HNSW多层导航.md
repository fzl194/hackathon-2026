# HNSW多层导航：怎样给底层找一个更好的入口

[Wiki首页](../README.md) · 前置：[HNSW查询手推](HNSW查询手推.md)、[HNSW](HNSW.md)

多个候选负责在当前图中保留搜索分支；多层结构则让查询先沿稀疏图快速定位，再把到达的节点作为下一层入口。两者作用不同，通常配合使用。

## 1. 层是现有节点的子集，不是聚类中心

底层L0包含全部点，上层只保留部分点。同一个点进入上层后仍是同一个向量，下层也依然存在；不是每层重新生成代表向量，也不是把3072维降到更低维。

典型HNSW为节点随机抽取最高层数，多数点只在底层，越往上节点越少。层数在构图时决定，不是查询到来后才挑出接近它的点。

## 2. 给上次的人工图增加一层

仍取q=(4,4)，K=1。括号内是到q的L2平方：

```text
L1：        H(50) ───────── E(4)
             │              │
             │ 同一个H      │ 同一个E
             ↓              ↓
L0： A(18)—B(8)—H(50)—F(9)—E(4)—D(1)—C(2)
                  |
                 G(32)
```

上层只放H和E，并连一条H-E边。这是人工安排的教学层次，不是实际运行随机层分配和构图的结果。

图中的上下箭头表示同一节点跨层的对应关系；每层有自己的邻接表。上层H-E边不要求也出现在底层。

## 3. 在上层先贪心走

从最高层入口H开始：H到q距离平方50，它的上层邻居E为4，因此移到E。E的上层邻居只有H，不能继续改善，于是在E下降到L0。

```text
上层：H(50) → E(4)
下降：从底层同一个E开始
```

上层不必直接找到最近的D。它没有D这个节点；任务是为底层提供一个有希望的入口。典型查询在高层采用贪心导航，底层再进行更充分的候选搜索。

## 4. 底层仍然使用多个候选

令ef=2，继续用前一篇的邻居顺序。E的底层邻居按D、F检查：

|步骤|动作|Q|W|
|---|---|---|---|
|初始化|入口E|E(4)|E(4)|
|1|扩展E，D(1)加入，F(9)不加入|D(1)|D(1)、E(4)|
|2|扩展D，发现C(2)，E已见|C(2)|D(1)、C(2)|
|3|扩展C，D已见|空|D(1)、C(2)|

最后按K=1返回D。

从H直接在底层搜，前例依次扩展H、B、F、E、D、C；上层帮助我们从E进入底层后，底层只扩展E、D、C。上层导航本身也有成本，这不是实际QPS对比，不能忽略它来宣称加速倍数。

## 5. 多层与多候选分别贡献什么

|机制|直觉|控制或依赖|
|---|---|---|
|多层导航|先快速接近目标区域，再在底层细找|层次、入口和各层连边质量|
|多个候选|保留几条有希望的路径，减少单条贪心路径的限制|efSearch/ef、候选队列和停止规则|

高层也会遇到无法继续改善的位置，底层搜索也有预算限制。两者是在提高导航效率和找到好答案的机会，不是保证永远逃出所有局部最优。

## 6. 与IVF、粒子群和本题怎样对应

IVF通过中心选择列表；HNSW通过实际数据节点上的图导航选择继续访问的点。候选保留可借用“不要过早丢掉其他有希望方向”的优化直觉，但HNSW查询不会对向量做交叉、变异或移动坐标。

对于第14题，还要继续问：这些邻接表和向量在内存还是SSD？一层层找到了好入口，并不消除底层随机读盘成本。连接数量、搜索预算与缓存都要在实际内存限制下测量。
