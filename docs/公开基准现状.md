# 第14题相关公开基准：成绩、条件与可比边界

核查日期：2026-10-21。这里回答“别人已经做到了什么”，不把历史成绩当作本题当前最高成绩。本项目尚未跑过任何性能基准。

## 1. 先看结论

十亿规模磁盘ANN、3072维搜索、过滤和动态维护都有公开实现或实验，不需要从零发明整个领域。但这些能力分别成立，不代表某个现有PG扩展同时满足本题全部要求。

目前没有取得本题正式VM、调度脚本和可比的PG18.4成绩。所以下面能说明技术可行性、提供复现入口，不能直接用于预测比赛排名。

## 2. 核心ANN：十亿规模已经有磁盘方案

[DiskANN 2019原论文摘要](https://papers.nips.cc/paper_files/paper/2019/hash/09853c7fb1d3f8ee67a61b6bf4a7f8e6-Abstract.html)报告：

|数据|资源|公开结果|
|---|---|---|
|SIFT1B / BIGANN，10亿点|16核，64GB RAM＋SSD|超过5000 QPS，平均延迟低于3ms，1-recall@1超过95%|

含义：数据远大于内存时，利用SSD仍可以做高吞吐近邻搜索。

比较边界：这是2019年的独立ANN系统，衡量最近1个点的1-recall@1；本题主要看recall@10及曲线面积，还要求PG集成、事务、过滤和动态能力。因此5000 QPS不是本题保底目标，也不是截至2026年的最高水平声明。

BIGANN 10M/100M在本题相同资源下的成绩仍未知。规模、线程、数据编码、缓存、索引内存和召回目标改变后，不能按比例外推。

## 3. 高维：读取作者原始结果，先核对数据和K

题面写`simplewiki-openai-3072`为100万条。[VIBE当前作者目录](https://github.com/vector-index-bench/vibe#evaluation)列出`simplewiki-openai-3072-normalized`为260,372条、3072维，并放在deprecated datasets中，表示后续不再更新该数据的结果。这与题面条数不一致，必须让官方确认实际文件；不能默默改题面。

作者说明CPU结果使用Intel Xeon Gold6230、单核，GPU结果使用V100 32GB，且比较的是算法实现，而非数据库服务。[实验说明](https://github.com/vector-index-bench/vibe#results)

本次实际读取了作者[固定提交的summary.parquet](https://github.com/vector-index-bench/vector-index-bench.github.io/blob/9841a87385af0a2ce43efd61fca70dd7c4f40b4b/results/summary.parquet)，该文件提交日期为2026-07-31，不代表每条实验均在当天运行。读取到这个数据变体的K全部为100，不能当作本题Top-10成绩。

以下对四个用于入门的实现，分别选取文件中“作者Recall≥0.95时QPS最高”的实际参数点；没有插值，没有筛选全部算法做排名：

|作者实现名|作者Recall@100|QPS|关键参数|
|---|---|---|---|
|hnswlib|0.96243|481.55|M=8，efConstruction=500，efQuery=200|
|ivf(faiss)|0.95827|82.66|n_list=2048，n_probe=64|
|ivfpqfs(faiss)|0.96447|411.42|n_list=512，dim_reduction=0，n_probe=32，k_factor=2|
|vamana(diskann)|0.99239|269.86|complexity=128，graph_degree=64，alpha=1.2，search_complexity=100|

如何读表：这几个实际点表明，不同组织方式和压缩组合会明显改变速度；它们的召回并不完全相同，尤其Vamana这一点接近0.992，不能据此断言它比0.962召回的HNSW慢。要比较，需要完整曲线及相同资源约束。

还要保留两个源码层面的边界：

- 作者当前[导出实现](https://github.com/vector-index-bench/vibe/blob/main/export_results.py)使用第K个真实邻居的距离加0.001作阈值，统计返回前K个中距离达标者，再取平均。这是作者的距离容差口径，不能严格等同ID集合交集/K；上表按原文件`recall`字段保留。
- VIBE的[Vamana适配源码](https://github.com/vector-index-bench/vibe/blob/main/vibe/algorithms/diskann/module.py)调用`build_memory_index`和`StaticMemoryIndex`，使用单线程；这里的Vamana结果是内存版，不能拿它证明SSD版或PG版表现。

完整选点、参数、原始字段、查询条件、来源提交与SHA256保存在[选点记录](references/vibe-simplewiki选点.json)。原始`index_size`字段也被保留，但本次未核实单位与测量口径，不将它解释为磁盘索引字节数。

## 4. 过滤：同一数据上，专门设计会有很大差别

[Big-ANN公开结果表](https://github.com/harsha-simhadri/big-ann-benchmarks/blob/main/neurips23/ongoing_leaderboard/Azure_D8lds_v5_table.md)注明最近评估为2024-03-01，下面是其中两个开源算法参照：

|数据|算法|QPS|共同条件|
|---|---|---|---|
|YFCC-10M过滤|Faiss|3032.53|public queries；取recall@10≥90%的最高QPS|
|YFCC-10M过滤|ParlayIVF|37902.11|同上|

[榜单硬件说明](https://github.com/harsha-simhadri/big-ann-benchmarks/blob/main/neurips23/ongoing_leaderboard/leaderboard.md)：Azure Standard D8lds_v5，8vCPU、16GiB内存。

含义：同一公开过滤任务中，专门设计的数据组织和执行方式可能比通用基线快很多。不能只拿无过滤ANN算法加一个事后判断，就假定能竞争。

边界：这是历史公开查询结果，不是本题当前成绩；表中只列两个用于理解的实现，不代表冠军排名。90%召回下一个点，也不等于本题[0.80,1.00]整段曲线面积。

## 5. 动态：先复现确定的历史基线

[NeurIPS23基准README的Baselines节](https://github.com/harsha-simhadri/big-ann-benchmarks/blob/main/neurips23/README.md)给出：

|数据和工作负载|算法|公开结果|
|---|---|---|
|msturing-30M-clustered＋final_runbook.yaml|DiskANN基线|recall@10=0.883，用时45分钟|

该任务约束为1小时、8GB DRAM；上游运行VM总内存16GiB，CPU说明为Xeon Platinum8370C。VM物理内存与算法允许使用的内存不是同一个数。

含义：在不断插入、删除的过程中保持召回，是一个已经有公开复现入口的任务。这里0.883是该文档的历史基线，不能称当前最好、PG18.4成绩或本项目成绩。

上游另有10M、`delete_runbook.yaml`的0.924/23分钟结果，那是不同工作负载，不与上表混用。ongoing榜正文的最高召回叙述与其所链接CSV存在不一致，本次不据此宣称动态赛道的当前最高数字。

## 6. 我们该怎样建立自己的可比成绩

第一步先在小数据上得到独立精确答案，保证指标算对；第二步选定一个可编译的PG基线，记录功能缺口；第三步在相同内存、CPU和SSD上跑参数扫描；第四步扩大到超内存并覆盖过滤和动态。

每条成绩至少需要数据文件/版本、距离、K、召回定义、源码提交、构建参数、搜索参数、线程/并发、内存限制和测量范围。数据库实验还要说明是否包括SQL调用、表记录访问、可见性检查和日志代价。

这些条件没对齐时，公开数字用于建立直觉；条件对齐后，我们的实际曲线才用于决定优化方向。具体实验矩阵见[实施与验证](实施与验证.md)，学习顺序见[入门与学习路线](入门与学习路线.md)。
