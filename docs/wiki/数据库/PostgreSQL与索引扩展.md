# PostgreSQL 与索引扩展

[返回 Wiki 首页](../README.md) · [第14题全貌](../第14题全貌.md)

**一句话：PostgreSQL 是管理数据的数据库软件；索引扩展为它增加一种寻找数据的方式。**

## 从你熟悉的数据结构理解

假设内存里有一个记录数组，记录包含编号、文章和向量。遍历数组可以完成搜索，但数据多时会慢。

于是你维护一个哈希表或搜索树，让程序少检查一些记录。数据库索引也有这个目的：额外组织数据，减少查询工作。

区别是数据库还负责磁盘存储、多个用户并发操作、提交与撤销，以及崩溃恢复。索引要在这些条件下继续正确工作。

## 表、索引、SQL 分别是什么

|概念|先这样理解|
|---|---|
|表|保存记录的主要结构，例如每行存编号、标签、向量|
|索引|为某些查询维护的加速结构，会占空间，也要维护|
|SQL|用户描述需要哪些数据的语言|
|查询规划器|估计不同执行办法的成本，选择执行方案的组件|

下面是依赖 pgvector 类型与运算符的三维示意，假设表已经存在：

```sql
SELECT id
FROM documents
ORDER BY embedding <-> '[0.1, 0.2, 0.3]'::vector
LIMIT 10;
```

意思是“按 L2 距离升序，取最近10条”。用户表达需求，数据库可以扫描所有向量，也可能采用适用的向量索引。

普通 B-tree 擅长一维排序及范围查询。高维近邻关系通常不能靠一个简单的一维排序高效解决，所以需要专门的索引。

## 一次查询怎样走到索引

```text
SQL 查询
  → 规划器比较可用的执行方案
  → 执行器调用索引提供的搜索能力
  → 检查记录可见性、过滤条件等
  → 返回结果
```

这是一幅入门流程图；可见性和过滤由哪层检查、能否提前检查，取决于具体执行方案及索引实现。

扩展是 PostgreSQL 的功能包，可以加入类型、运算符、函数或索引访问方法。仅提供一个 SQL 函数，不等于已经实现完整的索引访问方法。

## 与第14题的关系

题目要求把磁盘向量搜索接入 PostgreSQL。现成 ANN 库可以提供搜索算法，但它自己的文件不自动获得 PostgreSQL 的事务与恢复保障。

我们还需要支持建索引、持续插入、查询，以及与删除清理、并发和恢复机制的协作。索引存在也不保证每次都会被规划器选中；要通过执行计划确认实际路径。

## 易混淆点

- PostgreSQL 是数据库；pgvector 是扩展；HNSW 是算法；DiskANN 是算法实现项目，它们不在同一层。
- 索引通常不替代表。可以只保留定位信息，也可以额外保存向量等内容，取决于设计。
- 索引能持久化到磁盘，不代表数据远超内存时仍然快；后者需要实际测量。
