# HNSW插入与选边手推

[Wiki首页](../README.md) · 前置：[HNSW查询手推](HNSW查询手推.md)、[HNSW多层导航](HNSW多层导航.md) · 下一篇：[HNSW参数与构建代价](HNSW参数与构建代价.md)

HNSW通常逐点构建：把新点当查询，在已有图中寻找邻居候选，再选边并维护邻接表。本页手算选边，数据与候选集为教学构造，不是实际运行完整HNSW构图所得。

## 1. 插入流程先看完整一遍

第一个点直接初始化入口。后续新点X的基本过程：

1. 随机决定X的最高层ℓ；X会出现在第0层到第ℓ层。
2. 从已有最高层入口开始，把X的向量作为搜索目标。高于ℓ的层主要用于贪心导航，不给X连边。
3. 从X与旧图共有的最高层开始向下，在每个相关层进行构建搜索，维护规模由efConstruction控制的候选集合。
4. 从候选中选择至多M个合适邻居，给X写入连接，并尝试在旧邻居处加入反向连接。
5. 旧节点连接数达到该层上限时，要重新筛选其邻居。
6. 继续处理下一层。若X比原来所有点的层数都高，更新全局最高层与入口。

例如旧图最高L2、新X最高L1：先在L2导航，再在L1和L0搜索、选边、连接。上层选过邻居不表示底层可以不搜索；不同层包含的点和边不同。

本页忽略重复编号更新、删除与并发细节。HNSW没有先计算全部点对距离的必要；已有图同时承担“帮助插入新节点”的任务。

## 2. 假设某层搜索找回这些候选

新点X=(0,0)，设M=2。为了集中解释选边，假设该层候选为A、B、C、D、E；不假设所有真实图都必然找回这个集合。

|候选|坐标|到X的L2平方|直觉方向|
|---|---|---|---|
|A|(1,0)|1|右|
|B|(1.1,0)|1.21|右，紧挨A|
|C|(0,1.2)|1.44|上|
|D|(-1.3,0)|1.69|左|
|E|(0,-1.4)|1.96|下|

如果只选最近2个，就会连接A、B。两条直接连接都通向很相近的位置。

这里的新X既是将插入的节点，也是本次构建搜索的目标向量。日后用户的查询可以在其他位置，索引需要帮助许多不同查询导航。

## 3. 更近的边，不一定带来更好的导航

考虑插入后的另一个查询t=(0,2)，从X开始：

|节点|到t的L2平方|
|---|---|
|X|4|
|A|5|
|B|5.21|
|C|0.64|

如果X的直接邻居只有A、B，单步贪心无法从X改善；如果有X-C，就能一步到更近的C。多个候选或更高层有时还能帮助绕路，但不能因此忽视底层连接质量。

这是固定入口、局部边选择的教学比较，不是完整索引的召回或速度实验。其他旧边如何连接仍影响全局效果。

## 4. 用距离判断候选是否过于重复

本例采用此次读取的hnswlib `getNeighborsByHeuristic2`的主要规则：按候选到X的距离由近到远考虑；若候选c比起X，更靠近某个已选邻居r，即d(c,r)<d(c,X)，就跳过c；否则可以保留，直到选够预算或候选耗尽。

用L2平方比较不会改变这个大小关系。它通过候选之间的距离减少重复覆盖，不是硬性要求每个方向各选一个，也不需要直接计算夹角。

### 第一步：选A

A最近，当前没有已选邻居，因此保留A。

### 第二步：检查B

```text
d²(B,X) = 1.21
d²(B,A) = (1.1−1)² = 0.01
0.01 < 1.21 → 跳过B
```

B和已选A极近，从覆盖范围看较重复，给其他候选留位置。

这个规则并没有检查A是否真的有一条边连接B，不能把跳过理解为已经证明“X→A→B一定可达”。它是图导航启发式，不是安全剪枝证明。

### 第三步：检查C

```text
d²(C,X) = 1.44
d²(C,A) = (0−1)² + (1.2−0)² = 2.44
2.44 > 1.44 → 保留C
```

到此已有A、C，达到M=2，停止选边。D和E是因预算已满而未继续处理，不能说它们也被判定为重复。

|候选|处理结果|理由|
|---|---|---|
|A|保留|最近且尚无已选点|
|B|跳过|比起X，更靠近已选A|
|C|保留|没有被已选A遮挡|
|D、E|不再处理|已选够2个|

最终X初始选择A、C，而不是距离最近的A、B。图的目标不只是让每个点的邻接距离尽可能小，还要提供有用的导航路径。

## 5. M变大时，选边会怎样

仍用相同候选和规则：

- M=3：在A、C后检查D。d²(D,A)=5.29、d²(D,C)=3.13，都大于d²(D,X)=1.69，因此选D。
- M=4：再检查E。到A、C、D的平方距离分别为2.96、6.76、3.65，都大于d²(E,X)=1.96，因此选E。

得到A、C、D或A、C、D、E。增加预算让这个例子覆盖更多区域；不代表每份数据都会如此，也不保证参数增大带来严格单调的收益。

## 6. 还需要改旧节点的邻接表

X选A、C后，不仅要保存X的邻居，还要尝试让A、C的邻接表包含X。

如果旧A已达到该层连接数上限，就把旧邻居与新X一起作为候选，以A为中心重新选边。此时比较的是到A的距离，而不是继续套用前面到X的排序。

例如M=2时，此次读取的hnswlib底层上限是2M=4；旧A已有4个邻居，再加入X就需要在5个候选中重新筛选。初始新点选边预算与旧节点该层容量要分开。

在这种实现里，反向连接重选后可能未保留X，也不会自动保证所有旧边两端都完全对称。因此可以理解为尝试双向连接，不能把最终图无条件当成严格无向图。前面查询手推刻意用无向图，是教学简化。

## 7. 此处的边界

选边策略有不同版本和可选步骤。本例按hnswlib所读实现解释，其启发式可能得到少于M个邻居，不必自动补满。若输入候选数已经少于M，该实现会直接保留这批候选，不运行同样的筛选；不能把所有小候选池都当作前面的裁剪过程。HNSW论文中的选项及其他PG实现不能不加核对地照搬。

构图好坏与插入顺序、层次随机性、候选覆盖、M和efConstruction共同有关；并发、事务、日志和恢复则是第14题额外需要落实的工程机制。
