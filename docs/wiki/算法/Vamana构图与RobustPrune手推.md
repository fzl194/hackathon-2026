# Vamana构图与RobustPrune手推

[Wiki首页](../README.md) · 前置：[HNSW插入与选边手推](HNSW插入与选边手推.md) · 下一篇：[DiskANN内存与SSD查询手推](DiskANN内存与SSD查询手推.md)

Vamana是图构建与搜索方法；经典DiskANN在它的基础上设计磁盘存储和查询。本页按2019论文的RobustPrune讲原理，人工算例不冒充当前软件的完整构图输出。

## 1. 与HNSW相通的部分

两者都会在已有图中搜索候选、挑选有限邻居、尝试增加反向连接，并在连接超限时重新筛选。查询也都会保留不止一条搜索机会；论文中的GreedySearch带有限候选列表，不是只沿单条路径严格下降的朴素贪心。

经典Vamana主要使用单层有向图和入口导航，而HNSW通过嵌套多层图帮助定位。不能只把HNSW上层删掉就当作Vamana，候选来源、剪枝和整体构建流程也有差别。

## 2. RobustPrune在做什么

给点p重选出邻居，参数R是连接上限，α≥1控制剪枝条件。先将搜索候选与p原来的出邻居合并，去掉p自身，再重选。

重复选择剩余候选中离p最近的a；选入a后，对其他候选b检查：

```text
α × d(a,b) ≤ d(p,b)  → 剪掉b
```

直觉是：只有当已选a相对p明显更靠近b时，才把这条直接连接视为足够重复。α越大，条件越难满足，单次剪枝越保守。

这不是检查实际a→b边已经存在，也不是证明查询永远不会漏。固定R后，多保留候选还会改变后续选边顺序，最终图不一定是较小α图的超集。

## 3. 换一组能看出α作用的坐标

本页重新指定p=(0,0)，R=3，合并后的总候选为A—E。与前一篇HNSW选边页不同，这里的C改为(1,1)，D、E也按下表指定；旧邻居已计入总候选，不额外隐藏其他点。

|候选|坐标|d(p,候选)|距离平方|
|---|---|---|---|
|A|(1,0)|1|1|
|B|(1.1,0)|1.1|1.21|
|C|(1,1)|√2≈1.414|2|
|D|(0,2)|2|4|
|E|(-2.1,0)|2.1|4.41|

本页d采用欧氏距离。若用平方距离手算，等价剪枝式必须是α²×d²(a,b)≤d²(p,b)，不能只把α直接乘到平方距离上。

## 4. α=1时

先选A，再看其他点：

- B离A为0.1，1×0.1≤1.1，所以B被剪掉。
- C离A为1，1×1≤√2，所以C也被剪掉。
- D离A为√5，大于它离p的2，保留。
- E离A为3.1，大于它离p的2.1，保留。

剩余候选D、E，接着选D。E离D为√8.41=2.9，仍大于它离p的2.1，因此E保留并被选中。

最后出邻居为A、D、E。对于本例无距离并列的候选，用此前hnswlib多样性启发式、M=3，也得到相同选边；不代表两种完整算法相同。

## 5. α=1.5时

仍先选A：

|候选|比较|结果|
|---|---|---|
|B|1.5×0.1=0.15≤1.1|剪掉|
|C|1.5×1=1.5>√2|保留|
|D|1.5×√5>2|保留|
|E|1.5×3.1>2.1|保留|

这次C没有被A剪掉，于是下一步选C。

C到D为√2，1.5×√2≈2.121>2，所以D仍保留；C到E为√10.61，乘1.5也大于2.1，E也保留。接着选D，达到R=3，结束。

最终出邻居为A、C、D；E是因预算已满而未继续选择，不是被A直接遮挡。

|规则与预算|本例选边|
|---|---|
|只取最近3个|A、B、C|
|此前HNSW启发式，M=3|A、D、E|
|论文RobustPrune，α=1，R=3|A、D、E|
|论文RobustPrune，α=1.5，R=3|A、C、D|

α的作用是改变“怎样的直接连接才足够重复”的尺度，不是无条件选择最远点。近点仍优先被考虑；更多候选和长程连接有机会降低导航跳数，但没有保证本例参数适合真实数据。

## 6. 构建流程不只差一个α

经典论文先初始化随机连接，再按随机顺序处理数据点：以该点为搜索目标，收集搜索过程已展开的节点，合并其原邻居后剪枝，增加反向连接并处理超限。论文整体采用两遍处理，先α=1，再用用户给定α。

候选来源也有区别：论文对比中，HNSW主要使用构建搜索结束时保留的较近候选，Vamana利用搜索中累计已展开的节点，因而还可保留一些不在最终最近名单里的导航机会。不同实现的visited命名可能指发现或展开，不能只看变量名就对应。

|方面|HNSW的常见设计|经典Vamana|
|---|---|---|
|入口导航|多层图先定位，再到底层|单层图，从入口展开|
|连接预算|M及分层容量规则|R出度上限|
|构建搜索预算|efConstruction|构建L|
|剪枝尺度|此前讲的多样性规则，无同名可调α|RobustPrune的α|
|查询预算|efSearch等|查询L，仍保留多条探索机会|

构建L与查询L属于不同阶段，不因为名字相同就必须设成相同数值。具体性能仍需统一数据、资源和召回口径比较。

## 7. 论文与软件版本要分开

2019论文是本页规则的依据。官方仓库当前main已是新的Rust架构，旧C++位于cpp_main且标为非活跃维护；cpp_main的occlude_list也包含遮挡比例、多轮阈值和距离函数等工程细节。

因此本页α=1.5的欧氏手算，不应当作给某个版本命令行填1.5后就必然得到相同边。实际代码若使用平方L2，参数语义及细节要另核对。图算法、存储实现与数据库事务能力也不能互相替代。
