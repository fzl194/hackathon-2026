# HNSW：用多层图导航近邻

[Wiki首页](../README.md) · 前置：[KNN与ANN](../基础/KNN与ANN.md)、[IVF](IVF.md)

HNSW全称Hierarchical Navigable Small World。它把向量组织成多层图，通过沿边导航减少需要访问的点。

## 从一层图开始理解

每个向量是一个节点，每个节点保存一些邻居编号。从入口开始，计算候选到q的距离，优先访问有希望的候选，再发现新的邻居。

你熟悉的骨架可以直接用上：邻接表、优先队列、visited，以及有容量限制的候选集合。

```text
入口 → 扩展邻居 → 更新候选 → 继续扩展 → 返回候选中的Top-K
```

这只是搜索骨架，不是完整伪代码；停止规则、候选结构、去重和边选择都会影响结果。

## 与Dijkstra的区别

Dijkstra主要比较从源点走来的路径长度。HNSW主要依据节点与查询q的向量距离选择搜索方向；图边是导航工具，不是要求最短化的道路代价。

到q看起来更近的节点，后续不一定通向真正答案。因此不能只留一个当前最优点然后无条件贪心结束，通常需要保留多个候选探索。

## 层次有什么作用

高层只包含部分节点，便于快速移动到接近目标的区域；逐层下降，到包含全部节点的底层进行更充分搜索。节点层数采用随机机制生成。

可以借用跳表“上层快速移动、下层细找”的直觉，但不能把跳表的复杂度和正确性分析直接照搬过来。

## 常见参数控制什么

|参数|直觉|
|---|---|
|M|连接数量预算，影响图大小、导航和维护成本，各层连接数上限以实现为准|
|efConstruction|构图时保留多少候选，影响构图质量与时间|
|efSearch|查询时保留多少候选，影响召回与速度|

图也不是简单地每点只连最近M个点。具有不同方向和跨区域导航能力的边很重要，否则容易局限在小区域。

## 与本题的关系

pgvector已有HNSW，可作为学习与验证参照。其索引能持久化到磁盘；本题关注的是数据超内存后的性能，而不是“HNSW完全不能存盘”。候选和图节点如果频繁随机读SSD，成本会与内存实验差很多。
