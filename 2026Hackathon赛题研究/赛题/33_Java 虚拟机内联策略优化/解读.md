# 33 Java 虚拟机内联策略优化：技术解读与研究结论

> 研究日期：2026-10-11。面向会编程、不了解行业的读者，按 ELI5 技能先类比再解释。官方要求以[原文](原文.md)及[官网](https://www.chaspark.com/#/races/competitions/1326726924167634944)为准；下面技术路线与工时是研究判断；官方事实、外部资料和待做实验分别标注，未开展实际解题实验。

## 先弄懂它在做什么

像把常去的小店搬进办公室：省掉每次出门的成本，还能把几个环节一起优化；但搬太多店，办公室挤满，走动和整理更慢。方法内联减少调用并扩大优化范围，也会膨胀编译图和机器码。

领域是 **JVM C2编译器／内联策略／真实性能工程**。方法内联把小函数搬进调用者，像把常去小店搬进办公室，减少往返还能合并优化，但搬太多会挤满办公室。本题要改真实HotSpot C2源码，让运行快、代码不膨胀且JVM稳定。

## 官方任务、提交与评分

修改OpenJDK jdk25u-dev/jdk-25.0.3-ga的InlineTree::try_to_inline（题目示例称try_inline，实际以源码为准），交patch+构建脚本+PrintInlining日志；不能点名函数或写死特定阈值。必须确定性、无新增crash/assert；若引AI需数据脚本且训练<1小时。

**计分与硬门槛：** 基础5例30、进阶5例55、Petclinic10、创新5；进阶>30%11、>10%7、5%—10%3、0—5%1，可劣化扣分。基础强调3%波动内有提升；边界与“劣化>-10%”文字需澄清。

先把“能提交合法结果”和“分数有优势”分开验证。优化动作是否有用，应以官方计分对象与完整链路验证，不以行业常用指标或演示效果代替。若未发布具体规则，不能假设所有细节与公开论文一致。

## 可执行方案与竞争力

**最小可交付方案：** 在原正确性检查不变前提下，加基于调用热度/当前IR余量的收益成本规则；开关可回退；全量基础JMH及日志回归。

**进阶路线：** 预算按热路径分配、动态保留IR余量，递归收益逐级衰减；用多轮独立fork/预热确认提升，不调特定方法名单。

**核心竞争力：** 热点收益对比IR/字节码膨胀成本，动态图预算与递归衰减；跨应用无回退且日志确定。建议先比较基础版与一次关键改动，用消融说明改进来自哪里；不要同时改多项后只看总分。

**降级与止损：** 关闭激进策略并回到原C2检查，以确定性安全策略交patch；没有真实提升时需诚实接受低分。交付必须保留一个经完整验证的版本，新优化只有验证通过后才成为最终提交。

## 技术栈、硬件与工作量

技术栈建议：C++ HotSpot、Java/JMH、OpenJDK构建、PrintInlining、perf、自适应预算。

硬件：官方Kunpeng920，建议ARM开发；gcc10.3.1、glibc2.34、bash configure/make images，不改模块配置；建议提前可用aarch64机器，大内存/CPU快以缩短JDK构建。

## 调研后的结论与动手入口

**结论：先完成确切JDK构建和可信JMH对照，再改一类内联决策。** 实际jdk-25.0.3-ga源码叫try_to_inline，题目示例try_inline不可机械照抄。交付是C2 patch和构建脚本，调用图优化只是思路。

**动手入口：** 读取should_inline/should_not_inline、profile和IR预算，保留注解、类初始化、递归等正确性检查；在大小/预算附近引入基于热度、字节码与当前余量的保守规则。源码已有间接递归检查，不能把新增检测当创新；只提高全局大小阈值也不等于泛化自适应。

**第一项小实验（待做）：** 原版与小改版跑热小函数、冷大函数、间接递归、深调用和多态JMH，独立fork并充分预热。观察耗时分布、编译时间、拒绝日志、机器码/节点规模和crash；同架构稳定提高且基础例不回退后才扩规则。只有x86或一次快结果不能证明鲲鹏收益，尚未执行实验。

**后续与时间边界：** 14天资产是aarch64目标构建、日志解析、代表性基准、Petclinic与回退patch；24小时按gcc/glibc约束构建官方基线，一次改一个决策点，末段稳定性与日志确定性检查。无需训练，AI可选且训练<1小时；节点/代码膨胀和JIT测量噪声是主要风险。缺ARM构建积累比缺GPU更致命，评分阶梯边界与负分文字仍需澄清。

**还需核实：** CPU鲲鹏920和官方基准才决定最终收益；JIT预热、GC、profile和OS噪声会产生伪改善。边界5%/10%/30%以及“劣化>-10%”计分文字有歧义；基础用例3%波动口径需确认。缺aarch64构建环境比缺GPU更关键；安全启发式也可能低分，无法保证10%性能目标。
