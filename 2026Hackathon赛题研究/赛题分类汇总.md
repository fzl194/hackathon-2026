# 赛题分类与研究结论

按任务本质分组，每题出现一次。下面列的是研究发现和解题入口，完整实验证据与方法边界见[34题逐项汇总](逐题调研结论汇总.md)。

## 数据驱动预测、迁移与信号恢复

先验证数据与监督目标、统计可分性或物理可辨识条件。若第一实验不能支持信号质量/泛化，不应先扩大模型。

|赛题|调研后的关键结论|先验证什么|
|---|---|---|
|[01 AI-QoE加密流量分类问题](<赛题/01_AI-QoE加密流量分类问题/解读.md>)|研究支持先从运输行为建模，而非先训练网络大模型。像隔着快递箱看送货节奏，分辨率影响下载需求，但缓存、编码和拥塞会改变节奏；所以末5秒平均码率不能直接等同清晰度。论文恢复的是请求/响应属性，不是腾讯视频三档分辨率，也不证明本题Macro-F1达到0.80。合理切入是比较末5秒、10秒及全30秒的突发量、空闲比例、包长分位数，判断前25秒是否带来稳定增益；IP和时间戳应先排除，避免把采集地点记成标签。|设计受控抓包实验：同一视频分别播放三档分辨率，再改变网络限速与播放缓冲；输入为30秒包序列，标签为末5秒档位。对照末5秒字节阈值、末5秒统计树、30秒多尺度统计树；按视频/采集会话留出，比较Macro-F1和混淆矩阵。只有跨会话仍提升，才保留复杂特征；这项实验尚未执行，也不替代官方验证。|
|[02 5G全栈网络的感知劣化溯源](<赛题/02_5G全栈网络的感知劣化溯源/解读.md>)|像外卖凉了，堵车与晚出餐可能同时出现，但必须分清哪个是源头、是否要二者同时成立。本题已有根因表达式标签，研究入口应是监督式规则归纳与趋势检测，因果图用于缩小候选，而不是先全量跑通用因果工具。Tigramite给时滞条件独立检验，不给本题布尔表达式；即便LPCMCI允许潜混杂，也可能留下方向不确定的图。缺少生成机制或干预数据时，不能保证观测资料唯一确定真值。|设计30维合成时序：A上升延迟使B上升，共同因子又驱动C，QoE由A AND(D OR E)触发；加入噪声和不同滞后。对照最大异常节点、相关排序、趋势候选+有界布尔搜索。判定看真值表达式等价率、下游B误报率以及86400秒/100事件的单线程时间，不看QoE分类准确率。该实验只用于排除明显错误路线，尚未执行。|
|[05 网络流量在异分布场景下的迁移学习算法](<赛题/05_网络流量在异分布场景下的迁移学习算法/解读.md>)|像靠车辆外观认公交，换城市后颜色不可靠。DANN通过域对抗抹掉域差异，但需要可见目标样本；本题最后域未见，不能把它当开箱万能迁移方法。更实际的结论是先找前31包中的稳定信息，去掉地址标识，并用跨域留出量测迁移跌幅。应用other也不是简单剩余标签，可能需要识别未知业务；域强行对齐有机会把不同类混合，必须与只训练源域的基线比较，负迁移时放弃。|设计公开或自采多环境数据：同一组应用在两种网络/不同时间采集，第三环境留作盲样。对照只用源域树、长度时间归一化树、小CNN，以及在允许目标无标签前提下DANN。按环境而非流随机切分，记录每类Precision/Recall、other误报、单条平均/最大CPU耗时；只有新环境稳定增益才保留迁移模块。尚未执行，公开标签与官方51类不等价。|
|[06 高噪场景下语音降噪的保真优化](<赛题/06_高噪场景下语音降噪的保真优化/解读.md>)|像地铁里听朋友说话，静音能彻底去噪却也把朋友抹掉。本题恢复未混响的干净音，不只是压背景。研究支持DSP+小循环网频域路线，训练数据按已公开SNR[-10,0]与30%RIR可提前造；因此未知官方文本不是从零训练的必要条件。RNNoise提供成熟小模型思路但原生48kHz、PCM/C接口，不能直接变成16kHz显式state ONNX；DNS仓库也不是本题混音公式/校准系数，必须重新对齐。|设计100段干净语音与多类噪声/RIR组合，留出说话人、噪声和RIR；对照直通、传统因果滤波、小GRU，输入每次[1,2,257,2]并显式state。比较PESQ、DNSMOS OVRL、弱辅音听感、延迟≤40ms、单核ORT帧时；先做短训练验证能否过拟合小集，再做留出泛化。尚未执行，小集过拟合不算正式效果。|
|[26 面向智能体 AI 的预算感知 Token 估计](<赛题/26_面向智能体 AI 的预算感知 Token 估计/解读.md>)|适合从CPU表格预测和区间校准入手，而非让LLM每个前缀重新猜成本。评分是覆盖真实值后按宽度/真实值扣分，95%覆盖率不是天然最佳；临近结束的小剩余量尤其惩罚宽区间。任务3还必须结合最终成功状态，预算足够但最终失败的轨迹不能自动判FEASIBLE。|拟以完整任务为划分单位，先留出任务再从各自轨迹采前缀。输入官方历史轨迹；对照类别中位数区间、结构特征分位回归、增加文本近邻后的模型。观测官方区间分、覆盖率、宽度/R、早晚前缀分数、两类宏F1和单次推理时间。继续判据是任务级留出总分提升且5秒内，随机混分同一轨迹前缀的高分不算证据。实验尚未执行。|
|[31 虚拟陀螺仪：三颗加速度计重建运动轨迹](<赛题/31_虚拟陀螺仪：三颗加速度计重建运动轨迹/解读.md>)|入口是刚体方程、时间连续和边界约束，不是先把9路时序扔进网络。传感器差分可消共同比力，得到α×Δr+ω×(ω×Δr)；ω二次项本身含符号歧义，官方静止起点和转动激励提供时间信息。三点可观测性取决于几何与运动，不能说任意三点每帧都能直接唯一求ω。|拟输入200Hz合成数据：已知传感器几何、从静止变速单轴→变轴旋转及非闭合平移。对照逐帧差分+积分、含端姿态/端速度的批量平滑；观测角速度方向/过零、姿态残差、整段位置和末位置误差，再分别加入偏置、方向误差和相关振动。仅在无噪声恢复正确且非闭合末位置不被压回0时继续标定，实验尚未执行。|
|[32 AI驱动的内存页智能预测与预取技术](<赛题/32_AI驱动的内存页智能预测与预取技术/解读.md>)|第一步应证明预取机制在目标负载和压力下有净收益，再增加训练模型；高命中率无法抵消采样、推理、带宽和内存污染开销。官方至少每负载一个模型，CPU训练可采用小Markov/树模型，无须大模型。内核环境、权限与业务访问可观测性比GPU资源更影响24小时交付。|拟先做机制对照：同一冷页负载分别无预取、人工可知访问模式的定时WILLNEED、真实collect/predict/prefetch。这里可知模式只用于自造负载验证搬页机制，不可用于正式未来信息。观测业务耗时、major_fault、采样CPU、预取字节、驻留和命中；若理想机制都不提速，先改时机/压力/接口而非加模型。实验尚未执行。|

## 向量、缓存与数据系统

先建立精确/合法参考与内存、I/O或召回计量。库的行业性能不能直接代替本题预算与评分。

|赛题|调研后的关键结论|先验证什么|
|---|---|---|
|[03 针对无线特征向量的最优化存储和计算](<赛题/03_针对无线特征向量的最优化存储和计算/解读.md>)|这是两张无线方向指纹的快速相似度计算，不必重建完整5G物理模型。关键机会在预处理不计时，可提前解包、重排和统计；关键限制是每用户结构不能大于128字节，不能只用更大的预计算换速度。Huffman压缩可能省空间却使随机内积解码更慢。CSI论文证明研究存在量化/编码路线，但向量MSE小不保证近正交对的相关性相对误差小；本题应该按最终评分式联合测速度、sizeof和平均误差。|设计四类128字节向量对：官方示例、密集随机、稀疏以及接近正交/极值。对照标量基线、同内存精确SIMD、4/6/8位编码候选；先检查每对结果与溢出，再以随机2000对计时。判定使用正式e和评分式，单列近零内积误差；任何newMem>baseMem或e>10%的候选丢弃。尚未跑此实验，不宣称已有加速倍数。|
|[04 多模数据向量索引压缩](<赛题/04_多模数据向量索引压缩/解读.md>)|已有多模态向量，所以无需训练Qwen3-VL；PQ/IVF等路线可能需拟合小型聚类或量化码本。像相册目录，每条只留60字节仍要准确找到最近照片：SQ8码流1024B/条必超预算，原维1bit也要128B/条，10M就是1.28GB，不含ID和导航。若冲600MB满分目标，需要更强的降维/编码压缩和紧凑导航；若2000MB准入上限确认，可先实测原维1bit配紧凑IVF导航，不能因为码流1.28GB就断言不准入。两条路线都须验证90%召回。Faiss可快速画PQ/OPQ曲线，RaBitQ有ARM实现可作候选，但它们的通用效果不等于本题90%召回。|设计10万→100万真实多模态向量实验，留出查询、精确L2求GT。对照IVF-PQ、OPQ+IVF-PQ、降维+RaBitQ，扫描码长/降维数/nprobe。判定先看Recall@10≥90%条件下最小完整文件B/条，再看batch1 p95和构建峰值资源；随机高斯只用于读写协议压测。尚未实测，不将1M达标外推成10M保证。|
|[07 数据库缓存数据极致压缩算法](<赛题/07_数据库缓存数据极致压缩算法/解读.md>)|像每张登记表都写同一串字段名，可以共享一份字段模板；但拿某个人资料不能拆整箱。研究结论是先尝试按schema分组的共享字典+行内压缩，避免整表列压缩的随机解码代价。RocksDB经验说明小块冷字典会压不动，且每次反序列化字典浪费CPU；它不证明本题R>9。Get要逐字节恢复，JSON解析后再序列化会改变空格、键顺序或数值写法，语义相同仍可能不合格。|设计百万行多schema的高/低重复及嵌套JSON，包含相同语义不同空格/数字写法。对照逐行zstd、共享字典逐行zstd、schema结构token+原字节片段；测R与四项最坏D，执行Set覆盖、Del旧值、并发/race与byte equality。判定首先R>9，再代入分式看是否总≥60；更高压缩却随机读恶化99%不算改进。尚未执行。|
|[14 基于磁盘的 PostgreSQL 向量索引](<赛题/14_基于磁盘的 PostgreSQL 向量索引/解读.md>)|已有PG扩展StreamingDiskANN证明不必从独立DiskANN服务开始：量化向量参与导航，原向量重评分，标签参与过滤；当前README列余弦、L2和内积，不能据此宣称L1、稀疏向量、bit汉明/Jaccard都满足。过滤中标签索引与任意WHERE后过滤也不同，低选择率下可能差很大。因此本题首要工作是成熟扩展的能力矩阵，而非先写一个新ANN算法。|第一实验用公开或自造3072维向量、精确top-k真值及不同选择率标签，做数据大于内存的建索引和查询；扫描搜索列表/重评分参数，记录recall≥0.8范围的QPS曲线、峰值RSS、磁盘字节和构建时间，同时插入、回滚、删除并重启后检查可见性。只有高维、磁盘搜索及事务闭环成立，才扩大到10M/100M及动态runbook；小例驻RAM结果不能通过该实验。|

## 上下文、检索与智能体执行

这些题的Agent含义不同，分别是可观测性闭环、上下文治理、模板查询、预算控制、模型/实例路由和网页执行；先跑通各自固定接口。

|赛题|调研后的关键结论|先验证什么|
|---|---|---|
|[10 面向AI自驱优化的终端OS可观测性自适应增强框架](<赛题/10_面向AI自驱优化的终端OS可观测性自适应增强框架/解读.md>)|像医生不是开全部检查，而是挑能分辨两个诊断的那项检查。普通RAG日志问答到建议就停止，没完成本题：必须自动找到源码分支、产可编译补丁、部署复现，并说明新证据排除了谁。HiTrace提供真采集入口，不提供根因算法。DMA场景也说明申请/close日志未必完整，dup和IPC引用会改变生命周期；信息增益的关键是记录决策条件和对象关联，而不是日志字数更多。|设计优先级未设置与传播失效两种故障，旧日志都只显示低优先级。对照全量打印、人工最小埋点、Agent按假设选点，记录标志源、传递中间值和最终决策。判定为补丁真实编译运行、新增证据准确区分故障，并测新增DFX字节/性能劣化相对基准；不用LLM解释漂亮程度做指标。尚未执行，案例不能替代官方跨模块故障。|
|[11 DevEco Code Agent上下文治理优化](<赛题/11_DevEco Code Agent上下文治理优化/解读.md>)|像把一摞材料整理成程序员工作台，压得薄不是成功，需求、失败断言和依赖如果被删掉就会写错。LLMLingua-2可作为可选压缩器，其自然语言保真不等于代码语义保真，不能保证100ms单次评分，也不保证测试通过率不降。SWE-agent支持改工具观察的工程路线，但不是DevEco插件。研究结论是先按内容类型做保守结构压缩：成功日志去重、错误保断言/栈、代码按符号依赖截取、用户约束原样保护；训练压缩模型不是起步必要条件。|设计跨文件改动、长会话需求变更、失败测试修复三类小任务；对照不压缩、结构去重、LLMLingua-2及结构+检索。用同模型与预算重复回放，看测试通过/约束遵守、token节省、端到端TTFT以及治理≤100ms。若token少但通过率下降或治理耗时抵消TTFT，就拒绝该策略。尚未执行，少数成功样本不能证明不劣化。|
|[13 云运维场景智能问数查询优化](<赛题/13_云运维场景智能问数查询优化/解读.md>)|BM25F允许资源类型、动作、字段分别加权，能够给模板一个低成本入口；它只按词项证据排序，不保证“区域、租户、否定词”完整保留，更不负责API正确执行。增加同义词虽改善召回，也可能把相近但不同的查询意图混在一起。竞争力来自模板归纳后的语义校验与拒答校准，单换检索公式不足以解决本题。|第一实验分三张成绩表：①10种原子意图各换实体、区域和说法，检查自动归纳模板是否在替换实体后仍生成正确API；②对相似意图、缺条件、库外问题比较原BM25与字段加权/n-gram召回，记top-k召回、误命中与拒答；③再测2—4原子组合的端到端行匹配与延迟。只有召回提高且错误执行不增加，才加同义扩展；原子执行不稳时不增加组合规模。|
