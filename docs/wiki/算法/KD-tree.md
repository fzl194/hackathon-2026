# KD-tree：分割空间，用距离下界剪枝

[Wiki首页](../README.md) · 前置：[KNN与ANN](../基础/KNN与ANN.md) · 下一页：[IVF](IVF.md)

KD-tree是一种组织多维点的树结构。它递归划分空间，查询时尽量跳过不可能改善答案的区域。

## 与线段树怎样类比

两者都用树组织区域，提前建结构减少查询工作。区别是线段树常维护一维区间的和、最大值等；KD-tree通常按某个坐标轴划分点集，节点对应一个空间区域。

二维示意：先按x坐标切分左右，再按y坐标切分上下。

```text
全部点
├── 左边
│   ├── 左下
│   └── 左上
└── 右边
    ├── 右下
    └── 右上
```

实际构建可选择不同轴和切分位置，区域大小也不一定相同。这张图只帮助理解递归划分。

## 最近邻查询为什么能跳过一个区域

查询q=(2,3)，已经找到一个距离为3的候选。另一区域所有点的x坐标都≥8，那么该区域离q至少6：只看x就差了6。

这个距离下界大于当前候选距离，因此整个区域都不可能更好，可以不访问。

找K个近邻时，先用堆维护K个候选，当前第K近距离为r；如果某区域到q的距离下界>r，就能剪枝。等距边界要按具体返回规则处理。

## 一次搜索的骨架

1. 优先访问看起来更接近q的子区域。
2. 到叶子后计算其中点的距离，更新候选堆。
3. 对尚未访问的区域计算距离下界。
4. 下界不能改善答案就跳过，否则继续访问。

这里的跳过有几何依据，因此可以做精确搜索；也可以引入近似策略进一步减少搜索，树结构本身不等于“必然近似”。

## 高维为什么困难

在一些高维数据上，许多区域的距离下界都不足以排除它们，搜索被迫访问大量区域。最后可能接近扫描全部点，还多了维护树和访问节点的成本。是否退化及退化程度与维度、分布、查询和实现有关。

不能因树高接近log N，就认定一次最近邻查询必然为O(log N)：一次查询可能进入很多分支。

## 与本题的关系

它帮助建立“空间换时间＋有依据的剪枝”的直觉。接下来学习IVF时，要观察分区搜索怎样通过有限搜索预算接受遗漏；不能只因为看见树就认定适合3072维或十亿规模。
